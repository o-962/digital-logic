2 · Base Conversions

Every conversion uses one of four moves: evaluate (any → decimal), divide (decimal integer → r), multiply (decimal fraction → r), or group (between bases that are powers of each other).

A. Any base → decimal (evaluate)

Multiply each digit by its weight rposition and add.

(10110.0101)2 = 16+4+2 + ¼+1/16 = 22.3125 · (16.5)16 = 16+6+5/16 = 22.3125 · (26.24)8 = 16+6+2/8+4/64 = 22.3125 (Book 1.9: all three are equal.)

Horner's method for integers is faster: (4310)5 → ((4·5+3)·5+1)·5+0 = 580.

C. Decimal fraction → base r (repeated multiplication)

Multiply the fraction by r. The integer part is the next digit. Repeat with the remaining fraction until it is 0 (or you have enough digits). The first integer is the MSB right after the point, so read top → bottom.

Mixed numbers like 15.625: convert the integer and fraction parts separately, then join them: 15 → 178, 0.625 → 0.58, so (15.625)10 = (17.5)8.
Many fractions never terminate. (0.6)10 = (0.2121…)4 and (0.1)10 = (0.0001100110011…)2. A decimal fraction terminates in binary only if its reduced denominator is a power of 2. When that happens, stop at the number of places the question asks for (1/3 to 8 places = 0.01010101).

D. Grouping: binary ↔ octal ↔ hex

8 = 2³, so each octal digit is 3 bits.
(10110.01)2 → 010 110 . 010 → (26.2)8
16 = 2⁴, so each hex digit is 4 bits.
(10110.01)2 → 0001 0110 . 0100 → (16.4)16
Group outward from the binary point: right-to-left for the integer part, left-to-right for the fraction. Pad zeros on the left of the integer and the right of the fraction. Padding the fraction on the left changes the value: .01 → .010 = 2, but .001 = 1 is wrong.

Octal ↔ Hex: go through binary (slides p.36). (26.2)8 = 010 110 . 010 = 0001 0110 . 0100 = (16.4)16

General rule: if base b = ak, then k digits of base a = 1 digit of base b. Base 3 → 9 groups 2 trits: (212.1)3 → 02 12 . 10 → (2 5 . 3)9. Base 4 → 16 groups 2. Base 2 → 32 groups 5.
